Cosco VPN vs Tailscale

Cosco VPN

  • IT ticket + specialist to onboard
  • Expensive-may require custom hardware
  • Appliance / gateway centered
  • Settings maze (IKE, PAC, split tunnel…)
  • Whole-network access mindset
  • Slow for “just share a preview”

Tailscale

  • Install client → authenticate → join
  • Peer mesh-no hardware setups required
  • Identity + tags + ACLs, not IP allowlists
  • MagicDNS names
  • Easy integration with existing CI/CD
  • Developer → Focus on business logic

Use case

Private preview of development/staging

  • Dev site on AWS EC2, shared over a Tailnet
  • MagicDNS URL + identity-based access
  • No public ports 80/443
  • Same pattern: internal staging or “show a friend”
  • Features stay private until production-ready

Access control

Tags = machine identity

tag:dev-server

Shared EC2 identity (not a person)

tag:ci

Ephemeral Actions nodes, deploy only

ACL

tag:ci → tag:dev-server:22 only

Humans

Member access for browse / SSH

OAuth scope

CI can mint keys for tag:ci only

Credential choice

Auth key on EC2, OAuth in Actions

EC2 → auth key

  • One long-lived server
  • tailscale up --auth-key
  • Stable MagicDNS hostname

CI → OAuth client

  • Ephemeral tag:ci node per Actions run
  • Created on demand when the runner starts
  • Revoked / gone when the job ends
  • Granular control: OAuth scoped to mint tag:ci only
